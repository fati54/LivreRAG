## Annexe B : Checklists et métriques

### B.1 Qualité des données
- [ ] OCR appliqué correctement
- [ ] Déduplication effectuée
- [ ] Encodage uniforme (UTF-8)
- [ ] Taux de texte exploitable > 90 %
- [ ] Métadonnées minimales présentes
- [ ] Version du document identifiée

### B.2 Gouvernance
- [ ] Filtrage PII actif (amont + aval)
- [ ] Droit à l’oubli (UUID, purge sélective)
- [ ] Cloisonnement multi-tenant
- [ ] Journalisation et audit complet
- [ ] Escalade humaine prévue

### B.3 Performance et coûts
- [ ] Caching embeddings et réponses
- [ ] k dynamique au retrieval
- [ ] Batching re-ranking et embeddings
- [ ] SLO latence p95 défini
- [ ] Budget LLM suivi par requête

### B.4 Déploiement
- [ ] Canary ou Blue-Green
- [ ] Migration d’index en double écriture
- [ ] Rollback transactionnel (prompts et policies)
- [ ] Feature flags par module

### B.5 Évaluation et métriques (cible prod)

| Catégorie | Métrique | Cible | 
|---|---|---|
| Qualité | Faithfulness | > 95 % |
| Qualité | Citation coverage | > 90 % |
| Retrieval | Recall@K | > 85 % |
| Retrieval | nDCG@K | > 0.75 |
| Performance | Latence p95 | < 3 s |
| Performance | Disponibilité | > 99.5 % |
| Gouvernance | PII leakage | 0 % |
| Gouvernance | Audit trail | 100 % |
| Coûts | € par requête (p95) | < seuil défini |
| UX | Trust score (CSAT) | > 8/10 |

### Comment mesurer
- **Faithfulness** : échantillonnage aléatoire, double annotation humaine, seuil d’acceptation ≥ 90 %.
- **Citation coverage** : vérifier la proportion de réponses contenant au moins une source valide et pertinente.
- **Retrieval** : constituer un jeu de vérité, mesurer recall@K et nDCG@K.
- **Process** : réévaluation hebdomadaire sur un échantillon représentatif pour détecter les dérives.

## Annexe C : Formats et templates

### C.1 Formats JSON type

**QueryEnvelope**
```json
{
  "query": "Quels étaient les protocoles COVID en 2020 ?",
  "user": {"role": "medecin", "lang": "fr"},
  "constraints": {"date": "2020-05-01", "confidentiality": "medical"}
}
```

**RetrievalResponse**
```json
{
  "docs": [
    {"text": "Protocole HAS 2020", "source": "pdf-123", "date": "2020-04-30"},
    {"text": "OMS guidance", "source": "who-2020", "date": "2020-05-01"}
  ]
}
```

**AuditEvent**
```json
{
  "request_id": "uuid",
  "user_id": "hash",
  "ts": "2025-09-03T10:15:22Z",
  "retrieval": {"topk": 8, "scores": [0.83, 0.79], "namespace": "legal"},
  "generation": {"model": "LLM-X", "prompt_id": "tmpl-12"},
  "verification": {"critic_pass": true, "policy_blocks": []},
  "citations": [{"doc_id": "D123", "chunk_id": "C9", "ver": "1.7"}]
}
```

### C.2 Pipeline minimal modulaire (YAML)
```yaml
pipeline:
  ingestion:
    ocr: true
    dedup: true
    metadata: ["title", "author", "date", "lang", "version"]
    pii_filter: ["presidio", "regex"]
  indexing:
    bm25: {enabled: true}
    vectors:
      provider: "sentence-transformers/all-MiniLM-L6-v2"
      dim: 384
    namespaces: ["public", "legal", "medical"]
  retrieval:
    topk_bm25: 8
    topk_vectors: 8
    rerank: {enabled: true, model: "cross-encoder/ms-marco-MiniLM-L-6-v2"}
  generation:
    model_router:
      - match: "legal"
        model: "LLM-legal-medium"
      - match: "default"
        model: "LLM-general"
    prompts:
      citations_required: true
  verification:
    critic_llm: "LLM-critic"
    citation_check: true
  governance:
    risk_governor:
      pii_block: true
      jailbreak_detection: true
      decisions: ["allow", "block", "reformulate", "escalate"]
  observability:
    tracing: "opentelemetry"
    metrics: ["latency_ms", "tokens", "pii_blocks", "faithfulness"]
```

### C.3 Politiques de sécurité (risk governor)
```yaml
policies:
  pii:
    ssn: "block"
    medical_record: "block"
    email: "reformulate"
  domains:
    health_advice:
      allow_only_sources: ["has", "who", "ansm"]
      fallback_on_missing_sources: "escalate"
  jailbreak:
    patterns: ["ignore previous", "disregard", "system prompt"]
    action: "block"
```

### C.4 Observabilité et alertes
```yaml
observability:
```

### C.5 Glossaire minimal

| Terme | Définition courte |
|---|---|
| RAG | Génération augmentée par la recherche documentaire. |
| Chunk | Fragment de document indexé et adressable. |
| Vector DB | Base optimisée pour la recherche par embeddings. |
| BM25 | Recherche lexicale classique (IR). |
| Re-ranking | Reclassement des candidats par un modèle spécialisé. |
| Critic LLM | Modèle qui vérifie la cohérence d’une réponse. |
| Risk governor | Module de conformité qui bloque ou reformule. |
| PII | Données personnelles identifiables. |
| TTL | Durée de vie d’un chunk avant expiration. |
